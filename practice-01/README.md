## 4. Задание 1. Один файл — две среды

| Способ запуска | Где появился вывод | Последняя строка |
|---|---|---|
| `node practice-01/js/hello.js` | в терминале | `Тип document: undefined` |
| `index.html` в браузере | во вкладке Console инструментов разработчика (не на самой странице) | `Тип document: object` |

Первые четыре строки совпадают. Различается только `typeof document`: объект `document` (DOM страницы) существует только в браузере. Node.js выполняет JavaScript вне страницы, поэтому такой переменной там нет и `typeof` возвращает `"undefined"` (без ошибки, потому что `typeof` можно применять к необъявленным именам).

## 5. Задание 2. Типы и преобразования

| № | Выражение | Ожидание до запуска | Фактическое значение | Тип | Объяснение |
|---:|---|---|---|---|---|
| 1 | `"8" + 2` | `"82"` | `82` | string | Если один операнд `+` — строка, второй превращается в строку и они склеиваются. |

## 6. Задание 3. Сводка выполнения задач (`progress.js`)

Порядок проверок: тип → `NaN` → целое → отрицательное → верхняя граница 1000 → выполнено больше общего → оба нуля → расчёт. После первой найденной ошибки выводится одно сообщение и сводка не печатается. Случай `0 / 0` обрабатывается до деления, поэтому деления на ноль нет. Статус определяется по исходным количествам, а не по округлённому проценту.

| Проверка | Входные данные | Ожидаемый результат | Фактический результат | Итог |
|---|---|---|---|---|
| Вариант 1, обычный случай | 12, 5 | осталось 7; 41.7%; «В работе» | Осталось: 7; Прогресс: 41.7%; Статус: В работе | Пройдено |
| Нет задач | 0, 0 | «Задач пока нет», без процента | Задач пока нет | Пройдено |
| Ничего не выполнено | 5, 0 | осталось 5; 0.0%; «Не начато» | Осталось: 5; Прогресс: 0.0%; Статус: Не начато | Пройдено |
| Всё выполнено | 5, 5 | осталось 0; 100.0%; «Завершено» | Осталось: 0; Прогресс: 100.0%; Статус: Завершено | Пройдено |
| Выполнено больше | 5, 6 | Ошибка | Ошибка: выполнено больше задач, чем существует. | Пройдено |
| Отрицательное | -1, 0 | Ошибка | Ошибка: количество задач не может быть отрицательным. | Пройдено |
| Дробное | 5, 2.5 | Ошибка | Ошибка: количество задач должно быть целым числом. | Пройдено |
| Строка | "5", 2 | Ошибка | Ошибка: количество задач должно быть числом, а не строкой или другим типом. | Пройдено |
| Верхняя граница | 1001, 0 | Ошибка | Ошибка: всего задач не может быть больше 1000. | Пройдено |
| NaN | NaN, 0 | Ошибка | Ошибка: недопустимое числовое значение (NaN). | Пройдено |

## 7. Задание 4. План по дням (`plan.js`)

Сначала проверяются все входные данные (включая `dailyLimit`, даже если задач не осталось). При ошибке цикл не запускается, поэтому бесконечного цикла быть не может. В цикле `while` на каждый день берётся `Math.min(dailyLimit, remaining)` — так в последний день не выполняется больше, чем осталось, и остаток не уходит в минус.

| Проверка | Входные данные | Ожидаемый результат | Фактический результат | Итог |
|---|---|---|---|---|
| Вариант 1 | 12, 5, 3 | 3 дня, в последний — 1 задача | День 1: 3 / ост. 4; День 2: 3 / ост. 1; День 3: 1 / ост. 0; дней: 3 | Пройдено |
| Делится нацело | 10, 4, 3 | 2 дня по 3 | День 1: 3 / ост. 3; День 2: 3 / ост. 0; дней: 2 | Пройдено |
| Норма больше остатка | 5, 3, 10 | 1 день, выполнено 2 | День 1: выполнено 2, осталось 0; дней: 1 | Пройдено |
| Всё выполнено | 5, 5, 2 | 0 дней, цикл не идёт | Все задачи уже выполнены; Потребуется дней: 0 | Пройдено |
| Нет задач | 0, 0, 2 | 0 дней, цикл не идёт | Все задачи уже выполнены; Потребуется дней: 0 | Пройдено |
| Норма 0 | 5, 2, 0 | Ошибка, цикл не идёт | Ошибка: дневная норма должна быть от 1 до 1000. | Пройдено |
| Дробная норма | 5, 2, 1.5 | Ошибка | Ошибка: дневная норма должна быть целым числом. | Пройдено |
| Выполнено больше | 5, 6, 2 | Ошибка | Ошибка: некорректное число выполненных задач (больше общего). | Пройдено |
| Норма строкой | 5, 2, "2" | Ошибка | Ошибка: дневная норма должна быть числом, а не строкой. | Пройдено |
| Норма больше 1000 | 5, 2, 1001 | Ошибка | Ошибка: дневная норма должна быть от 1 до 1000. | Пройдено |

## 8. Задание 5. Отладка (`debug.js`)

**Исходный вывод (с ошибками):**

```text
Выполнено: 32
Осталось: -24
Контрольная сумма: 6
```

**После исправления:**

```text
Выполнено: 5
Осталось: 3
Контрольная сумма: 10
```

| Ошибка | Что наблюдалось | Причина | Исправление | Результат после исправления |
|---|---|---|---|---|
| Обработка количества задач | `completedTotal` = `"32"` (тип string), «Осталось: -24» | `completedText` и `additionalText` — строки, `+` их склеил: `"3" + "2" = "32"`; затем `"8" - "32" = -24` | `Number(completedText) + Number(additionalText)` и `Number(plannedText) - completedTotal` | Выполнено: 5, Осталось: 3 |
| Граница цикла | `controlSum` = 6; на точке останова в цикле `taskNumber` принимал 1, 2, 3, при 4 цикл завершался | Условие `taskNumber < 4` не включает 4 | `taskNumber <= 4` | Контрольная сумма: 10 |

Отладка в DevTools: `debug.js` подключён в `index.html`, во вкладке **Sources** поставлена точка останова на строке вычисления `completedTotal`. До выполнения строки в **Scope** видно `completedText: "3"`, `additionalText: "2"` (строки). После **Step over** — `completedTotal: "32"`. Вторая точка останова внутри цикла показала значения `taskNumber` и `controlSum` на каждой итерации.

## 9. Вывод

Настроено окружение, один и тот же скрипт запущен в Node.js и в браузере. На практике разобраны неявные преобразования типов: самой показательной оказалась ошибка в `debug.js`, где сложение строк `"3" + "2"` не вызывает исключения, но молча даёт `"32"`, — программа «работает», а результат неверный. Поэтому в `progress.js` и `plan.js` входные данные сначала проверяются по типу, целостности и границам, и только потом выполняются расчёты; пошаговый план реализован циклом `while` с `Math.min`, чтобы остаток не становился отрицательным.
