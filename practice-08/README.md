## Запуск

Рабочая папка: `practice-08`. Нужны два терминала.

```bash
npm ci
npm test          # API + интеграция клиента + тесты хука
```

Терминал 1 — учебный API:

```bash
npm run api       # http://127.0.0.1:5505/api
```

Терминал 2 — интерфейс:

```bash
npm run dev       # http://127.0.0.1:5173/
```

Адрес API задаётся переменной `VITE_API_URL` (пример в `.env.example`).

## Структура

| Файл | Ответственность |
|---|---|
| `src/api-client.js` | HTTP-клиент из ПР5–ПР6: `requestJson`, тайм-аут, отмена, классификация ошибок `ApiError` |
| `src/task-api.js` | Методы задач из ПР6; фильтры дополнительно принимаются строками из React-формы |
| `src/config.js` | Один экземпляр `api` вне компонентов |
| `src/hooks/useTaskData.js` | Кастомный хук: загрузка, состояния `tasks` / `isLoading` / `error`, мутации |
| `src/App.jsx` | Фильтры, режим редактирования, вывод состояний загрузки и ошибки |
| `src/components/*` | Компоненты из ПР7, адаптированные к асинхронным операциям |

## Хук `useTaskData`

- `status`: `loading` → `ready` или `error`; `isLoading` и `tasks` вычисляются из него.
- При смене фильтров предыдущий GET отменяется через `AbortController`; ответ отменённого запроса игнорируется.
- При ошибке обновления сохраняется последний успешный снимок данных.
- Запись (`saveTask`, `toggleTask`, `deleteTask`, `resetData`) выполняется через общую функцию `runMutation`:
  флаг `pending`, отдельная `mutationError`, защита от двойного вызова, после успеха — новый GET с текущими фильтрами.
- Размонтирование отменяет и загрузку, и незавершённые записи.
