## Структура

| Файл | Ответственность |
|---|---|
| `src/App.jsx` | Корневой компонент: состояния `tasks`, `filters`, `editingId`; вычисляет видимый список и статистику |
| `src/components/TaskFilters.jsx` | Кнопки статуса «Все / В работе / Завершенные» (активная выделяется), поиск, приоритет, категория, сброс |
| `src/components/TaskList.jsx` | Условный рендеринг: «Список задач пуст» / «Задачи не найдены» / список через `.map` |
| `src/components/TaskItem.jsx` | Карточка задачи и кнопки «Завершить», «Изменить», «Удалить» |
| `src/components/TaskForm.jsx` | Управляемая форма создания и редактирования |
| `src/components/TaskStats.jsx` | Всего / выполнено / в работе |
| `src/domain/task-service.js` | Чистые функции: фильтрация, статистика, добавление, изменение, переключение, удаление |
| `src/domain/form-validation.js` | Проверка черновика задачи (перенесена из ПР6) |

## Основные решения

- Данные хранятся только в состоянии React, после перезагрузки страницы восстанавливается исходный набор.
- Видимый список и статистика не хранятся в отдельных состояниях, а вычисляются на каждом рендере:
  `selectTasks(tasks, filters)` и `getTaskStats(tasks)`.
- Все изменения иммутабельны (`map`, `filter`, spread), функции обновления используют функциональную форму
  `setTasks(previous => ...)`.
- Форма получает `key={editingId ?? 'new'}`: при выборе другой задачи React создаёт состояние формы заново.
- `window.confirm` вызывается до `setTasks`, так как функция обновления состояния должна быть чистой.
- Значение `categoryId` из `select` приходит строкой и преобразуется в число при проверке формы.

## Индивидуальный вариант

После загрузки установлен фильтр «В работе»: всего 12, выполнено 5, в работе 7, найдено 7.
