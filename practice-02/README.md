## 4. Модель данных и функции

Задача — объект `{ id, title, completed, priority }`:
- `id` — положительное безопасное целое (`Number.isSafeInteger(id) && id > 0`), уникально в списке;
- `title` — строка, после `trim()` от 1 до 100 символов;
- `completed` — `true`/`false`, у новой задачи `false`;
- `priority` — `"low"`, `"medium"` или `"high"`, по умолчанию `"medium"`.

| Файл | Ответственность |
|---|---|
| `src/data.js` | исходные данные: `demoTasks` и набор варианта |
| `src/task-service.js` | вся логика: проверки, чтение, сводка, изменения; ничего не выводит |
| `src/main.js` | порядок действий и вывод в терминал |
| `checks.js` | автоматическая проверка контрактов функций |

Внутренние вспомогательные функции `validateId`, `normalizeTitle` и `hasTask` не экспортируются; ими пользуются `createTask`, `addTask`, `setTaskCompleted`, `renameTask`, `removeTask`, чтобы не повторять одинаковые проверки.

**Почему `id` не равен индексу:** индекс меняется при удалении или добавлении записей, а `id` — постоянный признак самой задачи. Например, после удаления `id = 7` задача `id = 10` переходит с индекса 3 на индекс 2, но её `id` остаётся 10.  
**Почему `getTaskStats` возвращает число, а не строку с процентом:** число можно дальше сравнивать и пересчитывать; округление `toFixed(1)` даёт строку и нужно только при выводе.  
**Какие объекты копируются при изменении задачи:** создаётся новый массив (`map`) и новый объект только для изменяемой задачи (`{ ...task, completed }`). Остальные задачи в новом массиве — те же объекты, что в исходном; поскольку их никто не меняет, это безопасно.

## 9. Вывод

По сравнению с ПР1 расчёты вынесены в функции, которые принимают данные и возвращают результат, а не печатают его: поэтому их можно проверять автоматически (`checks.js`) и переиспользовать в интерфейсе. Ожидаемые ошибки возвращаются как `{ ok: false, error }`, и вызывающий код сам решает, что с ними делать. Неизменность данных обеспечена тем, что функции изменения создают новые массивы (`[...tasks]`, `map`, `filter`) и новые объекты (`{ ...task }`), а не используют `push`/`splice` и присваивания свойствам; это проверено сравнением с исходными значениями. Исправленная ошибка — пропущенный `return` в стрелочной функции с фигурными скобками.
